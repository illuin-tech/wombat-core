# LLM Google Module

| Property           | Value                                                  |
|--------------------|--------------------------------------------------------|
| **Technical Name** | `tech.illuin.wombat-module.llm-google`                 |
| **Family**         | `LLM`                                                  |
| **Java Class**     | `tech.illuin.wombat.module.llm_google.LLMGoogleModule` |
| **Components**     | `activity-resolver` (`LLMGoogleActivityResolver`)      |

## Description

The **LLM Google Module** resolves LLM activity on demand from the [Google Cloud Monitoring API](https://cloud.google.com/monitoring/api/v3) (`projects.timeSeries.list`), reading the output token volumes generated by LLM workloads running on Google Cloud, such as Gemini models served through Vertex AI.

Unlike source-based modules, nothing is polled nor stored in Wombat's metric store: whenever activity is requested for a time range, the resolver queries that range with pagination, aligned on its resolution (`ALIGN_SUM` / `REDUCE_SUM`) and grouped by model. Each aligned point is attributed to the slot ending at its `endTime`. Each model is a separate service, with request count derived from its output tokens using `output-tokens-per-request`.

The module builds the Cloud Monitoring filter internally, selecting `aiplatform.googleapis.com/publisher/online_serving/token_count` and output tokens only. The optional `models` list narrows the query by `resource.labels.model_user_id`; omitted or empty means all visible models. There is no user-supplied filter or `dynamic-profile`.

`resource-name` selects the API scope: `projects/<project-id-or-number>`, `folders/<folder-id>`, or `organizations/<organization-id>`. These are the [resource names accepted by Google's time-series API](https://docs.cloud.google.com/monitoring/api/ref_v3/rest/v3/projects.timeSeries/list). Organization/folder scope does not guarantee visibility of every descendant project's Vertex AI metrics: metric availability and permissions still apply. Use a project scope when its metrics are not exposed through a broader scope. A Google folder contains projects, not the reverse.

There is no region filter. `location` is the country assumed for impact calculations, not a restriction on the serving region. All models in an asset share the configured provider, country, and average output tokens per request; use separate assets when these assumptions differ. Selecting all models should only be used when those shared assumptions apply.

Totals and timelines are computed from the resolver's evaluations, which carry their time ranges and measured token volumes. Google usage is fetched directly for each evaluation rather than read from Wombat's metric store.

Since Cloud Monitoring rejects alignment periods shorter than 60 seconds and only retains most metrics for 6 weeks, requested ranges should use a resolution of at least one minute and stay within the retention window.

Use this module when:
- You consume Gemini or other Vertex AI publisher models and want to track their real token usage.
- You serve models on Google Cloud infrastructure exposing token metrics to Cloud Monitoring.
- You want evaluations based on measured usage without running a metric collector, authenticated either with a service-account key or with Application Default Credentials.

### Authentication

Requests are authenticated with an OAuth2 bearer token scoped to `https://www.googleapis.com/auth/monitoring.read`. The identity used must have permission to read time series in the selected scope and access the relevant monitored projects (for example through `roles/monitoring.viewer`).

- **Service-account key**: when `credentials-key` is set, the referenced secret must resolve to the full JSON content of a Google service-account key.
- **Application Default Credentials**: when `credentials-key` is omitted, credentials are resolved through [ADC](https://cloud.google.com/docs/authentication/application-default-credentials) (`GOOGLE_APPLICATION_CREDENTIALS`, workload identity, attached service account, etc.).

## Configuration Specification

The module registers the asset type `tech.illuin.wombat-module.llm-google` (`LLMGoogleAsset`) with a profile configuration (`LLMGoogleProfile`).

For cross-cutting data formats such as `Country` and `LLMProvider`, refer to the [Generic Type Glossary](../type-glossary.md).

```yaml
id: "vertex-gemini-flash" # `String`, Required - Unique identifier for the asset.
environment-id: "production" # `String`, Required - Identifier of the environment (e.g. `production`, `staging`).
name: "Vertex AI - Gemini 2.0 Flash" # `String`, Required - Human-readable asset name.
google-url: "https://monitoring.googleapis.com" # `String`, Required - Base URL of the Cloud Monitoring API.
resource-name: "projects/my-gcp-project" # `String`, Required - projects/<id>, folders/<id>, or organizations/<id>.
credentials-key: "secrets.google.service-account" # `String`, Optional(default: null) - Secret resolver key for a service-account JSON key. Falls back to Application Default Credentials when omitted.
proxy-url: "http://proxy.corp.internal:8080" # Optional - HTTP proxy with an explicit host and port.
profile: # `LLMGoogleProfile`, Required - LLM profile and Cloud Monitoring query configuration.
  provider: "google_genai" # `LLMProvider`, Required - Foundation model provider (`anthropic`, `mistralai`, `openai`, `huggingface_hub`, `cohere`, `google_genai`).
  models: # Optional - Model identifiers to include; omitted or empty includes all visible models.
    - "gemini-2.0-flash"
  location: "BEL" # `Country`, Required - ISO 3166-1 alpha-3 (or alpha-2) country code where inference occurs.
  output-tokens-per-request: 500 # `Integer`, Required - Average output tokens per request, used to derive the request count from the token volume. Must be strictly positive.
```

## Basic Setup

A minimal configuration resolving Gemini output tokens using Application Default Credentials.

```yaml
id: "vertex-gemini-flash"
environment-id: "production"
name: "Vertex AI - Gemini 2.0 Flash"
google-url: "https://monitoring.googleapis.com"
resource-name: "projects/my-gcp-project"
profile:
  provider: "google_genai"
  models:
    - "gemini-2.0-flash"
  location: "BEL"
  output-tokens-per-request: 500
```

## Advanced Setup

### Multiple Gemini Models with a Dedicated Service Account

In an enterprise environment, several Gemini models are consumed from a shared Google Cloud project. Wombat runs outside Google Cloud and authenticates with a dedicated read-only service account whose JSON key is managed via Wombat's secret provider.

The example below tracks two models as separate services under one asset. Both use the same assumed country and average response length.

```yaml
---
id: "vertex-gemini"
environment-id: "production"
name: "Vertex AI - Gemini"
google-url: "https://monitoring.googleapis.com"
resource-name: "projects/corp-ai-platform"
credentials-key: "secrets.google.wombat-reader"
profile:
  provider: "google_genai"
  models:
    - "gemini-2.5-pro"
    - "gemini-2.0-flash"
  location: "NLD"
  output-tokens-per-request: 500
```

### Corporate Proxy

Set `proxy-url` on the asset to route Cloud Monitoring requests and OAuth credential token requests through an HTTP proxy, including HTTPS CONNECT tunneling. Omit it for the default HTTP transport. Proxy credentials, paths (other than `/`), query parameters, and fragments are not supported. For workload credentials that use local metadata services, ensure the proxy can reach those services or use service-account credentials instead.

```yaml
proxy-url: "http://proxy.corp.internal:8080"
```

## Migration from the Previous Google Configuration

- Replace `project-id: my-project` with `resource-name: projects/my-project`.
- Replace `profile.model: gemini-2.5-flash` with `profile.models: [gemini-2.5-flash]`.
- Remove `profile.dynamic-profile`, including its `filter`.
- Move model restrictions into `models`. Other arbitrary filter restrictions are not supported.
- Explicitly configured models retain zero-token slots. With all-model discovery, an empty report produces no activity because no model can be identified.
